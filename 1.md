# OpenRank 项目详细分析报告

## 一、项目概述

这是一个 **GitHub 开源项目工程成熟度分析系统**，主要目的是分析 Python 开源项目的依赖管理、环境配置、新贡献者友好程度等指标，帮助评估项目的工程质量和可维护性。

项目包含 **三个主要模块**：

| 模块 | 功能 | 技术栈 |
|------|------|--------|
| `data_analysis` | 数据采集与分析 | Python, GitHub API |
| `webapp` | Web 可视化仪表板 | Flask, Chart.js, Bootstrap |
| `github-import-analyzer` | 浏览器扩展 | Chrome Extension (Manifest V3) |

## 三、核心模块详细分析

### 3.1 数据分析模块 (`data_analysis/`)

这是项目的**核心引擎**，实现了完整的数据采集和分析流水线。

#### 3.1.1 `github_spider.py` - 分层采样爬虫

**功能**：从 GitHub 搜索 API 获取 Python 仓库样本，采用分桶采样策略确保样本多样性。

**核心技术流程**：

```
┌─────────────────────────────────────────────────────────────┐
│                    GitHub 分层采样流程                        │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 定义采样桶 (按 Star 数分层)                              │
│     ┌────────────────────────────────────────┐             │
│     │ 10-100 Stars    → 采样 200 个          │             │
│     │ 101-1000 Stars  → 采样 200 个          │             │
│     │ 1001-10000 Stars → 采样 200 个         │             │
│     │ 10000+ Stars    → 采样 200 个          │             │
│     └────────────────────────────────────────┘             │
│                          ↓                                  │
│  2. 构建查询条件                                             │
│     language:Python created:2023-01-01..2025-12-31         │
│     stars:min..max fork:false                              │
│                          ↓                                  │
│  3. 随机页面抓取 (避免只取前几页导致的偏差)                   │
│                          ↓                                  │
│  4. 从候选池中随机抽样 → 输出 sampled_repos_buckets.json     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**关键代码设计**：
- 使用 `requests.Session` + `Retry` 策略处理网络异常
- 遵守 GitHub API Rate Limit（每分钟休眠，避免 429 错误）
- 设置随机种子保证可复现性

#### 3.1.3 `step2_repo_import_vs_requirements.py` - 导入一致性分析

**分析目标**：检测代码中实际 import 的包与 `requirements.txt` 声明的依赖是否一致。

**核心技术**：

```
┌─────────────────────────────────────────────────────────────┐
│                    导入一致性分析流程                         │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 下载仓库 ZIP 包 (GitHub zipball API)                    │
│                          ↓                                  │
│  2. 遍历所有 .py 文件                                        │
│     └─→ 使用 AST 解析提取 import/from...import              │
│                          ↓                                  │
│  3. 解析 requirements.txt / pyproject.toml                  │
│     └─→ 支持 poetry 和 standard 两种格式                    │
│                          ↓                                  │
│  4. 对比计算                                                 │
│     ┌────────────────────────────────────────┐             │
│     │ missing_ratio = 代码引用但未声明的包 / 总引用          │
│     │ redundant_ratio = 声明但未使用的包 / 总声明            │
│     └────────────────────────────────────────┘             │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**AST 解析 import 语句**：

```python
def extract_imports_from_code(code: str) -> Set[str]:
    imports = set()
    tree = ast.parse(code)
    for node in ast.walk(tree):
        if isinstance(node, ast.Import):
            for alias in node.names:
                imports.add(alias.name.split(".")[0])
        elif isinstance(node, ast.ImportFrom):
            if node.module:
                imports.add(node.module.split(".")[0])
    return imports
```

#### 3.1.4 `step3_repo_dependency_staleness.py` - 依赖陈旧度分析

**分析目标**：检测依赖文件的更新频率，判断项目是否有"依赖腐化"问题。

**核心指标**：
| 指标 | 含义 |
|------|------|
| `max_staleness_vs_repo_days` | 依赖文件最后修改时间 vs 仓库最后更新时间 |
| `max_staleness_vs_now_days` | 依赖文件最后修改时间 vs 当前时间 |

**解读**：如果 `max_staleness_vs_repo_days` 很大，说明项目在持续更新代码但未更新依赖声明，存在潜在风险。

## 四、关键技术详解

### 4.1 GitHub API 调用策略

```python
# 创建带重试机制的 Session
def create_session(token: str) -> requests.Session:
    session = requests.Session()
    session.headers.update({
        "Authorization": f"token {token}",
        "Accept": "application/vnd.github+json"
    })
    
    retries = Retry(
        total=5,
        backoff_factor=1.0,          # 指数退避
        status_forcelist=[429, 500, 502, 503, 504],
        allowed_methods=["GET"]
    )
    adapter = HTTPAdapter(max_retries=retries)
    session.mount("https://", adapter)
    return session
```

### 4.2 Python AST 解析 Import

import ast

def extract_imports_from_code(code: str) -> Set[str]:
    imports = set()

### 4.3 TOML 依赖解析 (兼容 poetry 和 standard)

```python
def parse_pyproject_toml(content: str) -> Set[str]:
    data = tomllib.loads(content)
    deps = []
    
    # Standard [project.dependencies]
    if "project" in data and "dependencies" in data["project"]:
        deps.extend(data["project"]["dependencies"])
    
    # Poetry [tool.poetry.dependencies]
    tool_poetry = data.get("tool", {}).get("poetry", {}).get("dependencies", {})
    if tool_poetry:
        deps.extend(tool_poetry.keys())
    
    return {pkg.split("==")[0].lower() for pkg in deps}
```
